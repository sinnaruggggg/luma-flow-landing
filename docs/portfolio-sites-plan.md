## 1. 현재 상태 진단

| 항목 | 현재 (`/samples/:id`, 40개) | 문제 |
|---|---|---|
| 구성 | 업종 8개 × 스타일 5개 | 업종마다 **업체 1곳(같은 이름·같은 문구)**을 5가지로 바꿔 입힘 → 실제로는 8개 사이트 |
| 형식 | 전부 한 페이지 | "세부 페이지 포함형(회사 홈페이지)" 사례가 없음 |
| 코드 | 레이아웃 하나당 15~35줄, 공통 데이터와 공통 CSS를 공유 | 사이트마다 깊이가 얕고, 서로 비슷해 보임 |
| 시각 | 거의 모두 각진 고딕 + 큰 글자 + 얇은 선 | 감각적·차분함·기업형 같은 **분위기 차이가 약함**. 사진이 적음 |
| 기능 | 폼 1개 | 예약·쇼핑·탭 같은 "개발 실력"을 보여주는 장면이 적음 |

**쓸 수 있는 자산**
- 출처·라이선스가 기록된 업종별 사진 160장 (`public/agency-assets/photos`, Unsplash)
- 이미지 생성 스크립트 (`npm run generate:industry-images`, Gemini 키 필요)
- 사이트 화면을 캡처하는 Playwright 스크립트

→ **결론: 기존 40개를 고치기보다, "사이트 1개 = 독립된 폴더·고유 디자인"인 새 포트폴리오 체계를 만든다.**
기존 `/samples` 경로는 남겨 두고, 새 사이트가 충분히 쌓이면 목록에서만 교체한다.

## 4. 기술 구조

### 4-1. 폴더 — "사이트 1개 = 폴더 1개"
```
src/sites/
  _kit/                     # 동작만 공유 (모양은 공유하지 않음)
    SiteRouter.jsx          # /sites/:id/:page 하위 페이지 전환, 뒤로가기, 사이트 내부 404
    MobileMenu.jsx          # 햄버거 메뉴 (포커스 가두기, Esc 닫기)
    Reveal.js               # 스크롤 등장
    Tabs.jsx, Accordion.jsx, Carousel.jsx, BeforeAfter.jsx
    BookingMock.jsx         # 날짜·시간 선택 → 요약 ("시안이라 실제 예약되지 않음")
    CartMock.jsx            # 장바구니 상태 (localStorage 아님, 메모리)
    FormMock.jsx            # 검증 + "시안 안내" 완료 화면
    SampleBadge.jsx         # "나나웹 제작 시안 · 가상 업체" 고정 배지 + 나나웹 돌아가기
    moods/                  # 무드별 시작 토큰 (글꼴·색·모서리·간격·모션). 사이트가 덮어씀
  hangyeol-law/
    content.js              # 모든 문구·이미지 경로 (여기만 고치면 내용 변경)
    Site.jsx                # 고유 레이아웃 + 페이지 목록
    pages/Home.jsx, About.jsx, Practice.jsx, ...
    site.css                # .site-hangyeol-law 범위 안에서만 적용
  flowdeck/ ...
src/content/portfolioSites.js   # 목록용 메타데이터 (id, 이름, 업종, 무드, 형식, 페이지 수, 썸네일, 예산 구간)
```
- 각 사이트는 `React.lazy`로 따로 불러온다. 에이전시 홈의 로딩 용량이 늘지 않는다.
- CSS는 사이트 클래스 범위 안에서만 쓴다. 사이트끼리 스타일이 새지 않고, 기존 `editorial.css`와도 충돌하지 않는다.
- 글꼴은 사이트를 열 때만 불러온다 (Google Fonts / jsDelivr).

### 4-2. 주소
| 주소 | 내용 |
|---|---|
| `/sites/:id` | 시안 사이트 홈 |
| `/sites/:id/:page` | 하위 페이지 (홈페이지형·기능형) |
| `/projects` | 목록. 필터에 **형식(랜딩/홈페이지/기능)**과 **분위기**를 추가 |
| `/projects/:id` | 케이스 스터디 (아래 5장) |

기존 `/samples/:id`와 `/projects/:id` 경로는 유지한다 (회귀 방지).

### 4-3. 이미지 정책
- 사이트마다 **다른 사진 세트**(8~15장)를 쓴다. 같은 사진을 두 사이트에 쓰지 않는다.
- 우선순위: ① 보유 사진 160장 → ② Unsplash·Pexels 추가 (출처·라이선스·해시 기록) → ③ 부족한 것은 GPT 이미지 생성 (`docs/image-prompts/`의 프롬프트 사용, 저장 위치 `public/sites/<id>/`). 인물은 얼굴이 드러나지 않는 뒷모습·손·실루엣 위주
- 모든 사진은 1600px·WebP·200KB 이하로 최적화하고, 사이트 안 "사진 출처"에 표시한다.
- 의료진·변호사 같은 "인물 소개"는 실존 인물로 오해받지 않도록 실루엣·일러스트·뒷모습 사진을 쓰거나 "예시 인물"로 표기한다.

## 5. 포트폴리오 전시 방식 (에이전시 사이트 쪽)

**목록 카드** (`/projects`)
- PC 화면 + 모바일 화면 썸네일을 겹쳐서 보여준다.
- 형식 배지 표시: "랜딩 · 1p", "홈페이지 · 6p", "기능 · 예약"
- 무드 색상 칩 3개

**케이스 스터디** (`/projects/:id`)
1. 과제 설정 (가상 브리프: 업종, 대상, 목표)
2. 무드보드 (색 칩, 글꼴 견본, 키워드)
3. **사이트맵 도식** (페이지 구성)
4. 핵심 화면 3장 + 모바일 화면
5. 대표 인터랙션 설명
6. **[사이트 직접 보기]** 버튼

**홈 "01 작업" 섹션**: 새 사이트 중 무드가 겹치지 않게 6개를 고른다.

**썸네일 자동화**: 스크립트 한 번으로 모든 사이트의 PC(1440×1000)·모바일(390×844) 캡처를 생성한다 (`npm run capture:sites`).

## 6. 사이트 1개 제작 절차 (반복 루프)

1. **브리프**: 업종, 대상, 목표 행동, 무드, 형식을 `content.js` 맨 위에 적는다.
2. **무드보드**: 글꼴 2개, 색 5개, 모서리·간격·모션 규칙 확정
3. **사이트맵·섹션 목록**: 페이지별 섹션 순서 (다른 사이트와 순서가 겹치지 않게 점검)
4. **콘텐츠 작성**: 실제 업체처럼 구체적인 한국어 문구. 가격·시간표 같은 숫자도 현실적으로. 과장·허위 실적 금지
5. **이미지 준비**
6. **개발**: 레이아웃 → 반응형 → 인터랙션 → 가짜 흐름
7. **점검**: 360/390/768/1440 캡처 확인, 키보드 이동, 동작 줄이기, 콘솔 에러, 빌드
8. **등록**: `portfolioSites.js`에 추가하고 썸네일 생성

**완료 기준 (Definition of Done)**
- 첫 화면만 봐도 업종과 분위기가 구분된다.
- 다른 사이트와 **히어로 구조·글꼴·색이 모두 다르다.**
- 모바일 메뉴, 모든 링크·버튼·폼이 실제로 작동한다.
- 하위 페이지 간 이동, 뒤로가기, 새로고침이 된다.
- "가상 업체·시안" 표기가 있고, 가짜 결제·예약이 실제처럼 완료되지 않는다.

**작업량 예상**: 랜딩형 1개 ≈ 작업 1회, 홈페이지형·기능형 1개 ≈ 작업 2회
