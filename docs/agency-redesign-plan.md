## 1. 현재 진단 (1440 / 390px 실제 캡처 기준)

| # | 현재 상태 | 문제 |
|---|---|---|
| 1 | 히어로 = 4장면 키네틱 타이포(웹을 만듭니다 → 보고/찾고/닿게 → 사진 → 나나웹) | 포스터처럼 보임. **H1이 `sr-only`라 화면에 회사 소개·CTA가 없음**. 한 바퀴를 다 봐야 무슨 회사인지 앎 |
| 2 | 섹션 구성: 히어로 → 사례 6개 → 제작 과정 4단계 → 문의 폼 → 푸터 | "개발" 전문성을 보여줄 장치가 없음 (서비스 범위, 기술, 품질 기준, 가격, FAQ 부재) |
| 3 | 우측 세로 CTA "내 프로젝트 찾기" | 한글이 한 글자씩 세로로 쌓여 어색함. 헤더에도 주 버튼이 없음 |
| 4 | 사례 그리드 = 동일한 2열 카드 | 전부 같은 크기라 리듬이 없음. 카드에 "무엇을 만들었는지(기능·기술)"가 안 보임 |
| 5 | 문의 영역: "상담 내용 저장 모드" | 실제 접수가 안 되는 상태가 노출되어 신뢰감 하락 (실제 연락처 미정) |
| 6 | 푸터 | 사업자 정보·연락 채널 없음 → 실제 회사로 보이지 않음 |

**유지할 강점**: 굵은 한글 그로테스크 타이포, 종이색+잉크+포레스트 그린+코랄 포인트 색, 얇은 선, 모션 정지/동작 줄이기 지원, 40개 샘플 사이트, 조건 검색 흐름.

## 2. 콘셉트: **Craft × Code**

> "디자인 스튜디오의 감각 + 개발팀의 정밀함"

- **감각(Craft)**: 큰 타이포, 과감한 여백, 섹션마다 배경색 전환(종이 → 잉크 → 그린), 사진은 크게.
- **정밀(Code)**: 12컬럼 그리드 선, 섹션 번호(01—07), 모노스페이스 메타 정보(`React · 반응형 · 예약 연동`), 도면/스펙 시트 같은 주석 표현.
- 한 문장 포지셔닝(안): **"보기 좋은 화면보다, 작동하는 웹사이트를 만듭니다."**

### 디자인 규칙 (기존 DESIGN.md 유지)
- 그라데이션·네온·둥근 카드 금지 → 유지. 각진 버튼, 1px 라인.
- 색: `--paper #f5f5f2` / `--ink #172023` / `--green #263e43` / 포인트 코랄(히어로에서 쓰는 색) 1개만.
- 폰트: Pretendard(제목 750~850, 본문 400) + 메타용 모노스페이스 1종(현재 Courier New → JetBrains Mono 등으로 교체 검토).
- **가짜 고객사·가짜 후기·검증 안 된 수치 금지** → 모든 사례는 "가상 프로젝트" 표기 유지, 수치는 실측값만.

## 3. 새 홈 정보 구조 (위 → 아래)

| 순서 | 섹션 | 목적 | 핵심 연출 |
|---|---|---|---|
| 0 | **헤더** | 길 찾기 + 전환 | 메뉴: 작업 / 서비스 / 과정 / 비용 / FAQ + 우측 **[프로젝트 문의]** 채움 버튼 |
| 1 | **히어로** | 3초 안에 "누구·무엇·다음 행동" | 키네틱 타이포는 배경 레이어로 유지하되, **고정 H1 + 한 줄 설명 + CTA 2개(문의 / 작업 보기)**를 항상 보이게. 하단 정보 바: `기획 · 디자인 · 개발 · 운영` |
| 2 | **역량 티커** | 무엇을 만드는지 훑기 | 얇은 선 사이로 천천히 흐르는 텍스트: 브랜드 사이트 · 랜딩페이지 · 예약/결제 연동 · 관리자 페이지 · 반응형 · SEO (정지 가능) |
| 3 | **01 Selected Work** | 실력 증명 | 비대칭 그리드(큰 카드 1 + 작은 카드 2 반복). 카드 hover 시 샘플 화면이 위로 스크롤되는 미리보기. 메타에 기능·기술 태그. "가상 프로젝트" 라벨 유지 |
| 4 | **02 Services** | 제작 범위 명확화 | 4행 리스트(브랜드·기업 사이트 / 랜딩페이지 / 예약·커머스 기능 / 유지보수). 행 hover 시 오른쪽에 관련 샘플 이미지가 나타남. 각 행에 산출물 목록 |
| 5 | **03 Quality Spec** (잉크 배경) | "전문 개발" 인상의 핵심 | 이 사이트의 **실측** Lighthouse 성능·접근성·SEO 점수, 360~1440 반응형 검수, 웹 접근성, 관리자 페이지 제공 등을 **스펙 시트** 형태로. 화면 요소에 치수·주석선이 그려지는 도면 모션 |
| 6 | **04 Process** | 불안 해소 | 기존 4단계를 스크롤 고정(sticky) 타임라인으로. 단계별 기간·산출물·고객이 할 일 |
| 7 | **05 Pricing** | 문의 전 기대치 정렬 | 3개 패키지 "시작가" (금액은 대표님 확정값 필요). 기존 예산 필터 구간과 일치시킴 |
| 8 | **06 FAQ** | 마지막 망설임 제거 | 각진 아코디언 6~8개(기간, 수정 횟수, 도메인·호스팅, 유지보수, 관리자, 결제) |
| 9 | **07 Contact** | 전환 | 좌: 큰 문장 + 이메일/카카오 채널/응답 시간, 우: 기존 문의 폼. "저장 모드" 문구는 실제 연결 전까지 차분한 안내로 |
| 10 | **푸터** | 실존 회사 신뢰 | 화면 폭 전체 대형 워드마크 + 사업자 정보 + 메뉴 |

### 모션 원칙
- 한 화면에 움직이는 초점은 하나. 스크롤 진입 시 텍스트 줄 단위 마스크 리빌(짧게, 1회).
- 기존 방식 그대로 IntersectionObserver + CSS 중심 (framer-motion은 이미 설치되어 있어 필요 시만).
- 모든 모션: 정지 버튼 / `prefers-reduced-motion` / 화면 밖 정지 유지.
- 커스텀 커서·패럴랙스 과다 사용 금지 (전문성보다 가벼워 보임).

## 6. 대표님 확인이 필요한 항목

1. **주 고객층**: 소상공인·병원·카페 등 로컬 비즈니스 vs 스타트업·기업 브랜드 → 문구 톤과 가격 구간이 달라짐
2. **실제 정보**: 회사명(나나웹/나나정원), 이메일·카카오 채널·전화, 사업자 정보
3. **가격 공개 여부**: 패키지별 시작가 공개 / "상담 후 견적"만 표기
4. **히어로 강도**: 현재 키네틱 타이포 유지+정보 레이어 추가(권장) vs 새 히어로로 교체
5. **실제 포트폴리오**: 실제 납품 사례가 생기면 가상 샘플과 구분해 별도 표기
